Definitions and model boundaries

Accepted output satisfies the declared correctness, quality and service conditions. Throughput is accepted output per time; latency is one request’s elapsed time. Allocation reserves a resource; it does not establish productive work.

Memory: decimal GB means one billion bytes. The 12-billion-parameter examples use supplied state accounting, workspace and reservation values. Aggregate capacity is only a necessary screen; a partition still has to fit each device and execute correctly.

Energy: the 60-second traces use the same hypothetical system AC boundary. Waiting energy counts. Facility overhead is outside that account. Energy per result is undefined when accepted output is zero.

Batching: one execution instance, full groups of four, fixed execution times, empty initial queue, no network delay and no timeout. This is a mechanism illustration, not a simulation of Triton or an LLM scheduler. Real systems can use timeout, partial or continuous batching; their timings need measurement.

Job demand: four independent jobs repeat a 60-second cycle. Perfect staggering assumes no shared-resource contention or completion penalty. The phase trace does not model cooling dynamics, protective action or a safe electrical response time.

Acceptance: the last exercise combines separately bounded memory, request-timing and job-demand screens. Its values do not describe one measured machine. Passing the screens still leaves quality, implementation, failures and the facility boundary to validate.

  • MLCommons — MLPerf Inference: Datacenter: read Scenarios & Metrics, the benchmark-definition introduction and Power Measurements. Tests specify input patterns, metrics and quality; measured system AC power applies to the accompanying benchmark. No result tables or normative compliance rules are used.
